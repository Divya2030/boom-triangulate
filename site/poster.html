The hard part isn't finding a difference between a CPU and a reference model — it's deciding what a difference means.

The problem

Comparing a real CPU against a reference model is a standard way to find bugs. Chipyard already runs Spike next to BOOM, so running the comparison is easy.

The hard part is choosing what to test — and, when BOOM and a reference disagree, deciding what the disagreement actually is.

The core question

A difference can be four different things:
RTL bug · reference-model bug · allowed difference · test artifact

Prior fuzzers are strong at finding differences. We focus on the less-studied step: classifying them.

The loop — five CHIA blocks

The idea — triangulate two references

Two references turn “which side is wrong?” into a mechanical vote — over committed state only.

Honesty built in

  • Mechanical rules first — cheap cases settled before any model call.
  • High bar for “RTL bug” — unsure ⇒ not sure, never rounded up.
  • Provenance on every verdict; integrity check on every mutant binary.

Key result

THE SECOND REFERENCE CAUGHT A BUG THE FIRST MISSED

Vote beats single-oracle triage

A forwarding bug derailed the program, so one reference read it as a broken test. Both references agree, BOOM is the outlier → RTL bug.

Spike : … handler entry BOOM : ecall retired (no write) ← derailed vote : oracles agree · BOOM outlier → RTL_DEFECT

Honest limits

  • Planted bugs prove the method; no new organic BOOM bug found.
  • Single-core bare-metal can't reach SimFuzz-class discovery.
  • Two references agreed on all real state — oracle-bug case is designed-in, not yet shown.
  • A documented bug (misaligned load) didn't reproduce; the loop correctly kept BOOM clear.
