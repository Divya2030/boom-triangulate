The problem

Running the comparison is easy. Reading it is not.

Comparing a real CPU against a reference model is a standard way to find bugs, and Chipyard already runs Spike next to BOOM. The unsolved part is choosing what to test and, when they disagree, deciding what the disagreement is.

A single difference has four very different meanings:

RTL bugfault in BOOM
reference bugfault in an oracle

Prior fuzzers are strong at finding differences; we focus on the less-studied step of classifying them. We do not compete on raw discovery or throughput.

Honesty built in

  • Mechanical rules first — the easy cases are settled before any model call.
  • High bar for “RTL bug” — unsure means unsure, never rounded up.
  • Provenance on every verdict; an integrity check on every mutant binary.

The decision — a two-oracle vote

Two references turn “which side is wrong?” into a vote

BOOM = Spike = DromajoCLEAN
Spike = Dromajo  ≠  BOOMRTL_DEFECT
BOOM = one  ≠  other oracleMODEL_DEFECT
Spike ≠ Dromajo, BOOM matches neitherINCONCLUSIVE

Comparison is on committed architectural state only — retired PC, instruction bits, register writes — so the vote is mechanical, not a judgement call.

Proven in both directions

SEEDED RTL BUG

Oracles agree, BOOM is the sole outlier → RTL_DEFECT.

SEEDED SPIKE BUG

BOOM + Dromajo agree, Spike stands alone → the vote names Spike.

A single golden-model flow cannot make the second call — it sees a mismatch but cannot tell whether the CPU or the reference is wrong.

The loop — reusable CHIA blocks

1 hypothesize reads BOOM's RTL and ranks 400+ seams by file·line · 2 generate writes RISC-V tests aimed at them, behind a build/finish/work gate · 3 triage runs the co-sim and votes. Each block is a standalone, reusable CHIA block.

Key result

THE SECOND REFERENCE CAUGHT A BUG THE FIRST MISSED

Vote beats single-oracle triage

A forwarding bug derailed the program, so one reference read the cut-off trace as a broken test. Both oracles finish and agree; BOOM is the outlier → RTL bug, no matter how the difference looks.

The floating-point generator targets the hard seams — NaN-boxing, min/max with NaN, saturating float→int, signed zero, all five rounding modes. Results are forced into the integer file so all three models compare identically.

Two would-be RTL bugs were traced to uninitialized FP control state (exception flags, then rounding mode) in the test setup — not BOOM. The triage rejected both: a vote proposes, the exact instruction disposes.

Honest limits

  • Planted bugs prove the method; no new organic BOOM bug found on this harness.
  • Single-core bare-metal can't reach the VM / privilege / multi-core states where documented bugs live — the gap is reach, not detection.
  • No natural reference-model bug seen; the tie-break is shown with a seeded one.
